# Noda 1.0.2-beta.16

**Draft prerelease — not published.** This document is ready for the future GitHub release page after the checks below are completed. It does not announce an available download.

Noda brings quick capture, Markdown editing, optional local AI organization, a knowledge graph and source-linked chat into one Windows desktop app.

## Repository and licensing preparation

This candidate prepares the clean source repository, English documentation, brand assets and distribution notices. Noda's own new source version uses PolyForm Noncommercial License 1.0.0. Previously distributed MIT-licensed copies retain their original grants. Third-party software and models keep their own terms.

Fresh app profiles start in English. Existing saved language preferences are retained, and interface languages remain selectable in Settings.

The installed beta.15 app is a separate earlier build. This repository preparation does not replace or relicense that installed copy.

## Included processing fixes from beta.15

- Existing topic tags are reused when a note changes an action or schedule about the same subject.
- New topic proposals are checked against the full note and existing tag catalog. A note can remain untagged.
- Positive batch suggestions for note relationships receive an independent full-pair confirmation.
- Manual note persistence no longer requires a redundant whole-note embedding call.
- The unsaved-changes hint clears when the source is restored exactly to the saved text.
- Settings controls and the new-note editor have consistent spacing.
- Project-retry guidance uses the correct action across all ten interface languages.

The source baseline also includes the earlier CPU compatibility fix for the Qwen scorer. Beta.16 starts in English while retaining the existing selectable interface languages.

## Requirements and setup

- Windows 10 or 11 x64 with an AVX2-capable processor.
- RAM and disk requirements depend on the chosen local models; 16 GB RAM is the starting recommendation for the supplied profile.
- Internet is required for runtime preparation and model downloads. Once prepared, the normal note-processing and chat workflow uses local models.
- The installer and initial interface start in English. The app retains ten selectable interface languages. Supplied processing profiles support Russian and English.

## Known limitations

See [known dependency advisories](../security-known-issues.md). Vulnerable pinned components remain; this private testing candidate is not approved for public binary distribution.

- This is a beta. Generated titles, tags, links and answers require judgment and can be wrong.
- CPU inference can take minutes. One short note in the previous controlled check completed in about 4 minutes 6 seconds; this is an individual observation, not a general benchmark.
- Imported model compatibility and quality vary. Imported models have their own licensing conditions.
- A successful targeted test suite does not certify every configuration or a fresh installation.

## Before upgrading

Save edits, finish current processing, fully exit Noda and back up the project folders and app profile. Notes remain in their project folders. Chat history and settings have separate profile data.

Older builds may not read queue format 3. Restoring an older executable alone may be insufficient; retain a compatible data backup. See [the user guide](../USER_GUIDE.md).

## Publication gate

Before publishing an executable:

- [ ] Record the exact source revision and dependency manifests used by the build.
- [ ] Run the clean repository's checks and retain the actual results.
- [ ] Build the full Windows installer from that revision.
- [ ] Verify clean installation, first-run downloads and capture/edit/chat on a fresh Windows profile.
- [ ] Verify update and complete restart from the intended previous build without losing notes or queue sources.
- [ ] Interrupt a real test job, restart, and check recovery, source preservation and duplicate handling.
- [ ] Verify a backup restoration with synthetic data.
- [ ] Complete third-party license, model, asset and dependency review for the exact artifact.
- [ ] Triage current dependency advisories for source and bundled runtime components; resolve relevant high or critical findings before public binary distribution.
- [ ] Check the distributable for secrets, private data and unintended files.
- [ ] Add the installer's actual SHA256 checksum and clearly state its signing status.

Attach only the verified installer and its checksum file to the future prerelease. Model weights and local runtime caches are not source-repository contents. Previous workspace test counts or a locally patched installation do not replace verification of the final distributable.
