# Noda 1.0.2

Stable release preparation — Windows 10/11 x64 with AVX2.

The version is **1.0.2**, without a beta suffix. Publication remains pending:
the repository must stay private until the owner's required access protections
are active, and the open release findings below are resolved or explicitly accepted.

## Changes

- Notes open in formatted Markdown preview, including existing Obsidian notes.
  Switch to editing with the eye button; drafts survive mode changes and refresh.
- Saved connections and backlinks appear below the note body. Open related notes
  by mouse or keyboard; lists refresh in the active project's context.
- Setup uses the current uninstaller to prepare an upgrade rather than relying on
  a broken legacy beta uninstaller. Locked applications and redirected uninstaller
  paths are rejected before replacing files.
- Includes the coordinated dependency fixes from beta.17 and the local beta.18–19
  interface improvements. Optional AI stages can legitimately produce no tags or links.

## Install and update

The intended asset is `Noda-Setup-1.0.2-x64.exe` with a matching `SHA256SUMS.txt`.
The full source repository remains available separately; model weights are not bundled.

1. Back up project folders and `%APPDATA%\Noda`, and fully exit Noda through the tray.
2. Run Setup, retaining the current installation folder when updating.
3. Open Noda from the Start menu. New profiles start in English; saved choices remain.
4. Initial runtime and model preparation requires internet access and additional disk space.

The Windows executable is **unsigned** pending a code-signing certificate. No trusted
publisher identity is asserted. The app does not include automatic version updates.

## Verification and limits

- Isolated source suites: 739 Python tests and 28 subtests; 632 Node tests.
- Python branch-coverage measurement: approximately 36% across the curated runtime
  manifest. This is not complete application coverage.
- Native installer fixture: fresh install, normal upgrade, recovery from exit 2,
  locked-file rejection, reparse-point rejection and uninstall retaining external notes.
  This fixture uses its own application ID and does not modify the installed Noda.
- npm audit: zero reported vulnerabilities at preparation time. This does not cover
  all Python/native components or establish absence of security defects.

Clean-machine validation of the exact release installer, interruption recovery and
broad real-model evaluation remain separate checks. Older project backups may be
needed for a downgrade; replacing the executable alone does not revert queue formats.

[Known security issues](../security-known-issues.md) and [compliance scope](../COMPLIANCE.md)
remain applicable, including IPC/document-boundary hardening, experimental training
and import paths, and separate Accelerate, DiskCache and PT2 deserialization concerns.
Use trusted model sources and avoid attacker-controlled checkpoint/cache files.
The stable label is not a security, licensing or regulatory certification.
