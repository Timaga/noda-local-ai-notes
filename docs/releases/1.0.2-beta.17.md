# Noda 1.0.2-beta.17

Dependency security update for the private Windows beta.

## Changes

- Replace the dependency versions affected by the previous 19 GitHub alerts, including all five high-severity findings.
- Update compatible Python runtime and test-tool pairs together, retaining a hash-pinned Windows CPU environment.
- Update the two affected packaging glob consumers without replacing legacy APIs used by other build tools.
- Include pip 26.3 and refresh the exact-version third-party notices and source provenance.

The complete npm audit reports zero vulnerabilities. Separate Accelerate, DiskCache and PyTorch PT2 concerns remain; see [dependency security status](../security-known-issues.md). Other findings in [COMPLIANCE.md](../COMPLIANCE.md) are not resolved by this dependency update.

## Install or update

Use the versioned **Noda-Setup-1.0.2-beta.17-x64.exe** attached to this release. The repository remains private; downloads require an account with access.

1. Back up your project folders and app profile, save edits, and fully exit Noda through its tray menu.
2. Run this version's Setup and then open the installed Noda from the Start menu.
3. Allow the app to prepare the updated local runtime. Runtime and model downloads require internet access.

Existing project folders and profile data are stored separately from the installed application. This beta has no automatic updater. The previous beta.16 artifact is preserved and still contains its original dependencies.

## Verification and limits

Local Windows validation passed **739 Python tests, 28 subtests and 626 Node tests**, with no skipped tests. The new checks exercise real CPU inference and safe-weight loading, Dataset/Arrow storage, file locks, local file access, packaging filters and ASAR creation. Exact CI results, the source revision and installer checks are recorded in the release's **VALIDATION.txt**; verify the downloaded Setup using **SHA256SUMS.txt**.

The installer remains **unsigned**. Clean-machine installation, real downloaded-model inference, upgrade/recovery and backup restoration remain separate acceptance checks. Passing tests and addressing the original GitHub alerts do not constitute public-release security approval.

Project-owned materials use PolyForm Noncommercial 1.0.0. Third-party terms and previously granted MIT permissions remain unchanged.
